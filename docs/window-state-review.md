# 窗口状态修复代码审查

结论：代码审查、17项纯函数测试、离线开发检查与release编译通过，可进入打包应用人工验收。暂不建议发布：真实持久化与桌面边界尚未验证。未启动应用、未运行真实桌面、未提交或发布。

## 修复范围与审查依据

审查 `src-tauri/src/lib.rs`、`window_state.rs`、`window_geometry.rs`、`tauri.conf.json`，并对照本地 Tauri 2.10.3、window-state 2.4.1 生命周期源码。范围为普通窗口状态记忆、关闭落盘、启动工作区限制；程序坞无窗重建与插件全屏尺寸保护不作为本次准出条件。

## 核心审查结果

| 项目 | 结论与依据 |
| --- | --- |
| 持久化 | 关闭与失焦显式调用 `save_window_state`；API主动查询当前窗口，避免依赖插件CloseRequested内存更新顺序。插件Exit自动保存仍保留。 |
| 恢复顺序 | 隐藏创建，跳过插件自动恢复；恢复普通尺寸位置，约束工作区，恢复特殊显示模式，再show。排除VISIBLE，避免历史隐藏状态导致不可见。 |
| 无效状态 | 零尺寸与超u32尺寸跳过插件恢复，回配置逻辑默认大小并居中；恢复或约束错误记录后继续show，不传播setup。损坏JSON由插件按无历史处理。 |
| 像素单位 | 保存与恢复使用插件物理尺寸；工作区、外框和位置均物理像素；仅配置默认尺寸使用LogicalSize，避免高分屏倍增。 |
| 装饰与小屏 | 按outer减inner得到装饰差值，限制inner上限时扣除装饰；不新增固定min尺寸。零工作区在运行入口跳过。 |
| 多屏 | 使用current_monitor，缺失时primary_monitor；保留负坐标；恢复与resize将外框约束进工作区。Moved仅改尺寸限制，不钳位置，避免拖动到相邻屏幕被锁住。 |
| 重入与锁 | Limits使用try_lock，同步原生setter回调直接返回；尺寸上限缓存、setter差异比较和几何幂等避免持续重复。插件恢复锁导致其同步几何缓存回调跳过，未发现锁反序。异步原生事件仍须真实桌面验证。 |
| 最大化／全屏 | 这些状态与最小化跳过普通约束，保留插件原有状态恢复。插件全屏事件可能污染普通尺寸，列为既有已知限制。 |

## 已修正的审查问题

1. 初稿restore错误通过setup的`?`导致启动失败：已改为日志与默认回退，最终尝试show。
2. 初稿零尺寸仅几何max(1)会生成1×1：已读取历史尺寸做有效性校验，回配置默认尺寸。
3. 初稿Moved钳制position会阻碍跨屏：已区分Moved与resize/scale事件。
