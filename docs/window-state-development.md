# 窗口状态修复自测报告

## 原因与修复

本地 `tauri-plugin-window-state 2.4.1` 源码显示，关窗事件只更新内存缓存，只有应用退出才写状态文件。macOS 关闭窗口后进程可能仍保留，导致后续启动无法读到刚调整的窗口大小。新增关闭窗口及失去焦点时显式保存，插件原有退出保存保留；调整或拖动过程中不逐事件写磁盘。

插件恢复使用物理像素，且仅检查窗口与显示器是否相交，不保证窗口外框完整容纳在可用工作区。主窗口先隐藏，跳过插件自动恢复，在初始化时按“尺寸和位置恢复 → 工作区约束 → 最大化/全屏状态恢复 → 显示”执行。保存不包含可见性，避免隐藏启动状态被恢复成永久隐藏。

工作区约束使用物理坐标，包含菜单栏、任务栏、Dock 保留区域；内容最大尺寸扣除外框与内容之间的装饰差。普通窗口在恢复和缩放/尺寸变化后校正越界位置；移动时更新当前屏幕尺寸上限，不强制回退位置，因此允许拖动到相邻显示器。原生调用只在实际尺寸/位置变化时发生，尺寸上限缓存及互斥锁尝试获取防止同步递归事件。

零尺寸或超出原生尺寸类型范围的历史记录在恢复前被识别，回配置默认逻辑尺寸 1000×720，再按工作区限制。恢复或约束失败会记录错误并继续显示，不将历史状态错误传播成初始化崩溃。

## 可证伪假设及结果

1. 如果丢失状态来自“关窗但进程未退出”，关闭窗口时显式写状态文件应使本次几何可被下次进程读到。插件生命周期源码确认此原因；事件保存策略回归已先失败后通过，原生落盘仍需打包应用人工确认。
2. 如果巨窗来自恢复时仅做相交检查，将 2400×1800、位置 `(1500,-400)` 恢复到 1440×835 工作区应仍越界。纯几何回归已复现失败；修复后外框为工作区范围且所有边缘可见。
3. 如果仍越界来自把内容尺寸当作外框尺寸，1440×835 工作区、16×38 装饰差的内容尺寸上限应为 1424×797。回归先失败后通过，运行层使用同一尺寸转换函数。

## 限制

无界面进程的回归验证几何计算和生命周期策略，不能替代 macOS 原生事件、Dock、跨屏拖动与打包产物的人工验收。插件原有物理像素持久化不保证跨不同缩放比例保持相同逻辑尺寸，但恢复后按当前工作区限制外框。插件全屏事件可能覆盖普通窗口尺寸缓存是原有问题，本次没有新增全屏状态系统或 Dock 主窗口重建行为。
