# 窗口状态恢复：需求与验收标准

状态：代码与自动化范围产品验收通过；真实打包桌面体验待用户验证，未签署完整体验验收。

## 用户故事与范围

用户调整 Minidoc 窗口后，希望再次打开时保持上次普通窗口的大小和位置；更换屏幕或历史状态异常时，窗口仍完整可见、可拖动和关闭。适用于打包后的 macOS 主窗口正常退出并再次启动；关闭窗口时须落盘。应用没有主窗口时从程序坞重建窗口属于已有功能限制，本次不新增该入口。沿用当前默认尺寸 1000 × 720，无新增设置或界面，交互用以下流程定义。

## 交互与异常处理

调整普通窗口 → 保存最后有效大小和位置 → 退出并重开 → 读取历史状态 → 选择当前存在的目标屏幕 → 按可用工作区限制大小、修正位置 → 显示窗口。

- 有效历史状态优先恢复；目标屏幕消失或历史位置完全离屏时，回到现有屏幕内。有效负坐标副屏位置不应被误判为离屏。
- 超大窗口缩到目标屏幕可用工作区以内；越界位置移回工作区，窗口边框、标题栏及关闭入口均可见。工作区排除菜单栏、程序坞等系统保留区域；窗口装饰也计入边界。
- 缺失、损坏、零尺寸等无效状态使用默认值，再执行屏幕边界限制；不得阻止启动。实际工作区小于默认或最小尺寸时，以可见性为先。
- 高分辨率屏幕按缩放比例处理坐标与尺寸，不能把物理像素误当成逻辑尺寸。正常同屏恢复误差不超过 2 个逻辑像素。
- 最大化和全屏期间跳过普通窗口工作区限制。本次不新增记忆这些偏好的要求。现有 window-state 插件全屏状态可能覆盖普通尺寸，保留为既有插件限制，未在本次真实桌面验证。

## 验收标准

| 场景 | 操作与可量化预期 | 验证方式 |
| --- | --- | --- |
| 正常重开 | 改为 900 × 650 并移动到工作区内；完全退出并重开，普通窗口大小和位置与最后状态差异均 ≤ 2 逻辑像素 | 自动测试状态保存与恢复；真实桌面确认 |
| 关闭窗口保存 | 调整后关闭主窗口，即使进程尚未退出，状态也已写入磁盘；正常退出并重新启动后读取该状态 | 自动检查关闭事件显式保存；真实桌面待验证 |
| 无历史／坏历史 | 删除或注入损坏、零尺寸等历史状态；应用正常打开，默认窗口经限制后完整可见 | 自动测试；真实桌面确认启动 |
| 较小屏幕 | 在较大屏幕保存状态，再用较小屏幕启动；外框四边在该屏幕可用工作区内，能拖动、关闭 | 自动测试边界；真实桌面必须验证 |
| 超大／离屏历史 | 注入大于工作区的尺寸、部分越界位置和完全离屏位置；恢复后外框完整进入现有屏幕工作区，大小不超过工作区 | 自动测试各边界及组合；真实桌面确认 |
| 高分辨率／缩放变化 | 同一高分辨率屏幕重开不出现成倍放大；在不同缩放屏幕间恢复仍完整可见 | 自动测试单位换算；真实桌面必须验证 |
| 负坐标副屏 | 在主屏左侧或上方副屏保存有效位置并重开；仍在该副屏，不因负坐标回到主屏。拔掉副屏再开，完整回到现有屏幕 | 自动测试负坐标与移除屏幕；真实桌面必须验证 |
| 最大化／全屏边界 | 最大化、全屏时不执行普通窗口强制缩放；插件全屏普通尺寸覆盖风险另列限制 | 代码审查；真实桌面待验证 |

自动测试不能替代打包应用的屏幕缩放、工作区与窗口装饰验证。程序坞无窗重建与全屏普通尺寸保护不作为本次修复准出条件。未取得真实桌面结果的项目必须标记“待验证”，不得签署产品验收通过。
