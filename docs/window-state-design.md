# 窗口状态与工作区约束设计

## 问题与源码依据

项目已注册 `tauri-plugin-window-state`，无需另建状态文件系统。本地锁定版本 2.4.1 的源码显示：

- `CloseRequested` 只更新内存缓存，`RunEvent::Exit` 才写入配置目录的 `.window-state.json`。关窗与退出不是相同生命周期，因此需关窗时显式保存。
- 保存尺寸来自 `inner_size()`，位置来自 `outer_position()`，均为物理像素。
- 恢复先设置位置、后设置尺寸；监视器检测仅判断窗口角点是否落在屏幕矩形内，不限制尺寸，也不识别任务栏、菜单栏、Dock 所占工作区。
- 默认 flags 同时持久化可见、装饰、最大化、全屏状态。隐藏启动时不能继续恢复可见状态，否则历史隐藏记录可能造成窗口不显示。
- Tauri 2.10.3 创建配置窗口及调用插件 `on_window_ready` 后，才执行应用 setup。`Monitor::work_area()` 已提供物理坐标工作区。

## 实现边界

负责人：developer。保留现有插件、文件格式与配置目录，不更改文件打开或多实例行为。修改仅涉及主窗口初始化、几何约束、状态保存和对应测试。

1. 隐藏创建主窗口，插件跳过其自动恢复；setup 中显式恢复尺寸与位置，然后限制几何，再显示窗口。控制状态 flags，避免恢复 VISIBLE。
2. 普通窗口以外框与目标工作区比较。设置尺寸 API 接收内框，须扣除外框与内框差值，避免标题栏或边框超屏。
3. 多屏选择优先保留窗口所在屏幕；完全离屏或屏幕移除时移到可用屏幕。负坐标有效，不能统一钳制为零。恢复后整个外框应落在选定工作区。
4. 先缩小过大外框，再限制位置。全部计算保持物理像素，只有必要的逻辑尺寸配置通过对应屏幕比例转换。小屏以工作区上限优先，不让固定最小尺寸反向撑出屏幕。
5. 移动、缩放和比例变化后重算约束，比较目标与当前值后再调用 setter；以短生命周期保护避免同步事件重入，异步事件仍需幂等。
6. 关窗前显式调用插件保存，正常退出仍让插件保存。保存失败记录清晰错误，不能让状态失败阻断关闭。
7. 最大化、全屏及最小化状态不能用普通窗口约束强行缩放。window-state插件全屏resize可能污染普通几何缓存，本次按负责人确定的范围保留为已知限制，不扩展自建状态系统。

## 风险与验收

- 插件与应用窗口监听器顺序不能依靠猜测；保存 API 会主动读取现存窗口，关闭前调用即可捕获实际位置与尺寸。
- 多实例共用相同状态文件有最后写入者覆盖风险，沿用现有语义，不扩大本次实现。
- 跨不同 DPI 屏幕恢复保存的物理大小可能造成视觉大小变化；工作区约束必须可靠，是否转换逻辑视觉尺寸应另有明确需求。
- 自动测试覆盖普通尺寸保持、超大尺寸、负坐标、多屏移除、小屏与装饰差值、幂等性。编译覆盖 release。真实打包应用 GUI 不在本次运行授权内，须在交付时列出人工复核步骤。

核心审查：持久化时机、恢复顺序、物理与逻辑像素、装饰尺寸、多屏与小屏、事件递归、最大化与全屏。
